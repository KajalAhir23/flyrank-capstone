# How to add the next case study

Where it goes: a new `## Case Study: <name>` section in
`capstone-task-manager/README.md`, appended under "Related documents in
this repo" (or as its own top-level `CASE-STUDIES.md` if the README gets
too long).

Steps, next time:

1. Open my "My Portfolio & Case Studies" Claude Project (already has my
   voice, stack, and past case studies as context — no need to re-explain).
2. In one message, give it the three beats in plain language:
   - **Problem** — what was broken/needed, in one or two sentences.
   - **What I did** — the actual technical steps, real names (files,
     libraries, bugs), not vague summaries.
   - **What came of it** — the concrete result (a number, a fixed metric,
     a shipped feature, a before/after).
3. Ask it to draft the case study in the same three-beat shape as the
   existing ones, matching my established voice (direct, specific, honest
   about tradeoffs and mistakes — not just wins).
4. Review the draft, correct anything it got wrong or overstated, paste
   into the README, commit, push.

Total time from "I finished something" to "it's documented": under 15
minutes, because the Claude Project already knows the context.
